# 全局规则

## 语言设置

始终使用中文回复用户。无论用户使用何种语言提问，都必须用中文进行思考回答和交流。

此规则适用于所有会话,无论当前的工作目录和项目如何

## 权限受限设置

凡是遇到权限不足并且需要用户密码的情况,优先生成交互式权限确认脚本,并请求用户手动执行

## 文件检索与读取工具规范

- 查找文件:必须使用 `glob` 工具,禁止使用 bash 的 `find`/`fd`/`ls`/`tree`。
- 搜索文件内容:必须使用 `grep` 工具,禁止使用 bash 的 `grep`/`rg`/`ag`/`ack`,以及 `git grep`。
- 读取文件:必须使用 `read` 工具,禁止使用 bash 的 `cat`/`head`/`tail`/`less`/`more`/`bat`。
- 修改文件:必须使用 `edit`/`write` 工具,禁止使用 bash 的 `sed`。
- 切换目录:必须使用 bash 工具的 `workdir` 参数,禁止使用 `cd`。
- 搜索时始终限定在具体项目目录内,不要从用户主目录或根目录开始扫描。
- 例外:确有必要通过 shell 执行上述命令时,在命令末尾追加 `# confirm` 放行。

## 代码改动规范

- 修改代码前先阅读相关文件与周边上下文,理解现有风格与约定,不要凭空假设。
- 除用户明确要求外,不添加注释;遵循项目已有的命名与格式化习惯。
- 不要主动执行 `git commit` / `git push`,除非用户明确要求。

## 提交信息规范

- 提交信息遵循 Conventional Commits 格式:`feat:` / `fix:` / `refactor:` / `docs:` / `chore:` / `test:` / `perf:`。
- 提交信息使用中文描述改动内容。

## 验证要求

- 完成任务后,若项目提供测试或 lint/typecheck 命令,必须运行验证改动是否通过。
- 找不到验证命令时,询问用户,而不是盲目猜测。

## 交互原则

- 回答保持简洁、直接。
- 遇到需要用户决策的选择点时,优先使用提问工具让用户拍板,而不是自作主张。
